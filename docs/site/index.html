Anatomy

Five rings around one engine.

The model in the middle is the same one you use today. Each ring is code that runs in the agent's own hooks, so the habits hold on the hundredth task as well as the first.

  1. GuardsRING 1Every action is sorted before it runs, from a versioned policy file rather than the model's judgement.
  2. GatesRING 2The turn cannot end until a check passed after the last change. Sensitive work also needs attack tests and a clean scan.
  3. RouterRING 3Each request is matched to one of eleven procedures, with the gates that will be checked named up front.
  4. MemoryRING 4A mistake fixed once becomes a lesson with a trigger, recalled the next time the same situation comes up.
  5. MethodRING 5Plan, test first, build, prove, review: the steps a careful engineer follows, for any stack.
Safety that stays out of the way

Ordinary work runs. The rest waits for you.

Almost everything is ordinary and runs untouched. You are only asked about the few actions that reach outside your machine or cannot be taken back.

RUNSRecorded, never interruptedReading and editing code, tests, local builds, commits on your branch.
ASKSWaits for your yes, oncePushes, pull requests, deploys, sending messages, paid models. You approve the exact command in your own terminal.
STOPSRefused or made undoableReading .env files and keys, writing a live key into code, curl … | sh, skipping checks. rm -rf goes to a restorable trash.

What changes

Same request. Very different path.

The harness does not make the model smarter. It makes it follow the steps a careful engineer would, and it will not call the work done until the checks say so.

Data and team memory

A mistake one person fixes, nobody makes again

When the agent learns something the hard way, the harness writes it down as a lesson with a trigger. It comes back the next time, for you and, if you opt in, for the whole team.

Only lessons travel.A trigger and an instruction. Never code, prompts, file contents or personal data, and it is redacted twice on the way.
Reviewed before it spreads.The vault refuses anything that looks like a key or an identifier. A maintainer merges, then every agent recalls it.

Measured

Round 1 of our benchmark, 25 September 2026, on an earlier build: eight real tasks from easy to hard, the same model on both sides, scored by a separate judge that did not know which attempt was which.

The harness cost nothing in time, used fewer tokens and met more of the production checks. It lost five core points to three behaviours (a requirement reasoned away, an overclaimed summary, house style ignored). Each became a rule for round 2, which is measured the same way.

Install

Two minutes, once. Removed with one command.

The installer shows every change before it makes it and backs up every file it touches. A short onboarding runs the first time and never again unless you ask. This is the real onboarding, replayed.

  nodaris-harness onboardrecording

In a terminal

Python 3.9 or later, git, and a coding agent.

  1. Get the harness.
    git clone https://github.com/NodarisAI/Coding-Agent_Harness.git ~/.nodaris-harness-src
  2. Run the installer and answer a few questions.
    cd ~/.nodaris-harness-src && python3 install.py

Or let your agent do it

Send this sentence. The agent explains what will change, asks your permission, asks the setup questions, installs and proves the install works.
