      What you get
      
Eight habits, enforced by code, not by hoping the prompt sticks.

      
Most agent setups are a long prompt the model may or may not follow. The harness checks each action as it happens, in the agent's own hooks, so the habits hold on the hundredth task as well as the first.

    

    

  






  

    

      Safety that stays out of the way
      
Ordinary work runs. The rest waits for you, or does not happen.

      
Every action is sorted before it runs, from a versioned policy file rather than the model's judgement. Almost everything is ordinary and runs untouched. You are only asked about the few actions that reach outside your machine or cannot be taken back.

    

    

      
Runs
Recorded, never interrupted.

        
  • Reading and editing code
  • npm test · pytest · go test
  • Local builds and dev servers
  • git commit on your branch

      
Waits for your yes
You approve that exact command once, in your own terminal.

        
  • git push · opening a pull request
  • Deploys and remote commands
  • Sending an email or a message
  • Dropping a table · paid models

      
Refused or made undoable
With the reason, and what to do instead.

        
  • Reading .env files, SSH keys, cloud credentials
  • Writing a live API key into code
  • curl … | sh · skipping the checks
  • rm -rf, which goes to a restorable trash

Real output of nodaris-harness redact. Names, emails, phones, account numbers and dates become realistic stand-ins, so logs stay useful for debugging. For healthcare teams the same step covers patient identifiers, record and member numbers and X12 claim files, and a prompt holding patient data is stopped before it is sent.

    

  






  

    

      Team memory
      
A mistake one person fixes, nobody on the team makes again.

      
When the agent learns something the hard way, the harness writes it down as a lesson with a trigger. It comes back the next time the same situation does, for you and, if you opt in, for everyone on the team.

    

    

      

        
      

    

    

      
Only lessons travel.
A lesson is a trigger and an instruction: when this happens, do that, because. Never code, prompts, file contents or personal data, and it is redacted twice on the way.

      
Opt in, once a day.
Turned on during onboarding. It runs quietly at the start of a session, at most once a day, onto your own branch of the memory vault.

      
Reviewed before it spreads.
A check on the vault refuses anything outside your folder or anything that looks like a key or an identifier. A maintainer merges, then everyone's agent recalls it.

      Packs and proof
      
A general core, with depth where you need it.

      
Everyone gets the core. Onboarding asks what you build and adds the packs that fit; you can change them any time.

    

    

      
Core · every install
Engineering habits
Plans, tests first, proves, reviews and ships for any stack.

        
  • Request router with eleven procedures
  • Guards, approvals, redaction, reversible delete
  • Done gate, receipts and an "are we done?" loop
  • Lessons, a self-learning profile, code graphs

        
"Add paging to the export, it times out past 10k rows"

      
Healthcare · when chosen
Regulated data
For software that holds patient, claim or practice data.

        
  • Domain rules for claims, remittances and eligibility
  • A blueprint for new apps: tenancy, audit, encryption first
  • Patient-data checks in prompts, logs and test data
  • Self-attack tests on sensitive code

        
"Build a portal where clinics upload their remittance files"

      
Creative · when chosen
Web, motion and video
For sites, product films and terminal experiences.

        
  • Routes each request to the right tool and skill
  • Motion direction, scroll choreography, WebGL scenes
  • Product films from real screens, ffmpeg recipes
  • Terminal splash screens and animated CLIs

        
"Make a 20-second launch film of the new dashboard"

    

    

    

      
Measured against plain Claude Code

      
Round 1 of our benchmark, 25 September 2026, run on an earlier build of the harness: eight real tasks from easy to hard, the same model on both sides, scored by a separate judge that did not know which attempt was which, on ten core checks and five production checks per task.

      

      
Reading: the harness cost nothing in time, used fewer tokens and met more of the production checks; on one architecture task the plain agent shipped two live defects the harness avoided. It lost five core points, each to one of three behaviours (a requirement reasoned away, an overclaimed summary, house style ignored). Each became a rule for round 2, and round 2 is measured the same way.

    

  






  

    

      Install
      
Two minutes, once. Remove it with one command.

      
The installer shows every change before it makes it and backs up every file it touches. A short onboarding runs the first time you use it and never again unless you ask.

    

    

      

        
In a terminal

        
Python 3.9 or later, git, and a coding agent.

        
Get the harness.git clone https://github.com/NodarisAI/Coding-Agent_Harness.git ~/.nodaris-harness-src

        
Run the installer and answer a few questions.cd ~/.nodaris-harness-src && python3 install.py

      

      

        
Or let your agent do it

        
Open Claude Code, Codex or any agent in a terminal and send this sentence. It explains what will change, asks your permission, asks the setup questions, installs and proves the install works.

        
Install the harness from https://github.com/NodarisAI/Coding-Agent_Harness

        

        
For Nodaris AI staff, contractors and partners authorised in writing. The repository is private; ask a maintainer for access.
